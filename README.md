# Telegram AI-ассистент

[Открыть бота](https://t.me/GideonGrap_bot)

Бот принимает текстовые вопросы, обращается к AI API и отвечает с учётом
предыдущих сообщений. Вопросы и ответы хранятся в PostgreSQL. Пользователь
определяется по Telegram ID из обновлений Bot API, отдельный пароль не нужен.
Доступ открыт всем в личном чате. История у каждого своя.

Стек: Python 3.13, aiogram, HTTPX, SQLAlchemy, asyncpg, PostgreSQL 17, Alembic.
Запуск через Docker Compose. Интерфейса кроме Telegram нет.

## Запуск

Нужны Linux-сервер с Docker Compose, токен бота и ключ AI API.
Для локальной проверки подходят те же команды.

```bash
git clone https://github.com/SemGAA/telegram-ai-assistant.git
cd telegram-ai-assistant
cp .env.example .env
chmod 600 .env
openssl rand -hex 24
```

В `.env` заполните `BOT_TOKEN`, `AI_API_KEY`, `AI_BASE_URL`, `AI_MODEL`
и `POSTGRES_PASSWORD`. Для пароля базы используйте результат `openssl`.
API должен поддерживать `POST /chat/completions`. Пример настроен на OpenRouter.
Токены и `.env` не входят в репозиторий.

```bash
docker compose up -d --build
docker compose ps -a
docker compose logs --tail=100 bot
```

Если Docker требует права администратора, добавьте `sudo` перед командами.
Сначала запускается база, затем применяются миграции, затем стартует бот.
Состояние `Exited (0)` у `migrate` означает успешное выполнение миграций.

Бот использует long polling. Домен, HTTPS и открытые входящие порты не нужны.
PostgreSQL доступен только внутри сети Compose. Если у токена настроен webhook,
бот откажется запускаться: сначала нужно остановить прежний обработчик и удалить
webhook через Telegram Bot API. Не запускайте два экземпляра с одним токеном.

`ALLOW_ALL_USERS=true` открывает доступ всем. Чтобы ограничить его, установите
`false` и перечислите ID через запятую в `ALLOWED_USER_IDS`.

## Команды

- `/start` и `/help`: краткая справка.
- `/id`: Telegram ID пользователя.
- `/clear`: удалить свою историю из базы.

В модель передаются системная инструкция, последние 10 завершённых пар сообщений
и текущий вопрос. Контекст ограничен 24 000 символами, старые пары убираются целиком.
В PostgreSQL история хранится полностью до команды `/clear`.

Вопрос записывается до вызова AI. Затем сохраняется ответ или код ошибки.
Неудачные запросы не включаются в контекст. Запросы разных пользователей
обрабатываются параллельно. Второй запрос одного пользователя отклоняется,
пока первый не завершён, без постановки в очередь.

Лимиты по умолчанию: 4000 символов на вопрос, 1500 токенов на ответ,
8 одновременных запросов, пауза 3 секунды между вопросами, тайм-аут AI 40 секунд.
Длинные ответы делятся на сообщения. При ошибке API бот сообщает о ней без
технических деталей. Повторного платного запроса к модели автоматически не делает.

## Файлы

```text
bot/
  __main__.py       запуск, polling и завершение
  config.py         настройки окружения
  handlers.py       обработчики сообщений
  ai.py             HTTP-запросы к модели и контекст
  db.py             модели и запросы SQLAlchemy
migrations/         миграции Alembic
tests/              тесты API, базы и обработчиков
deploy/             адаптер Workers AI, если выбран Cloudflare
compose.yaml        PostgreSQL, миграции и бот
compose.test.yaml   отдельная тестовая база и тесты
Dockerfile          образ приложения и тестовый образ
```

`deploy/ai-worker.mjs` нужен только для Workers AI. Он преобразует запросы
Chat Completions в вызов модели Cloudflare. Это не Telegram-бот и не хранилище:
все обработчики и работа с PostgreSQL остаются в Python. Для другого AI API
этот адаптер не нужен. Настройка описана в [deploy/README.md](deploy/README.md).

## Тесты

```bash
docker compose -f compose.test.yaml up --build --abort-on-container-exit --exit-code-from tests tests
docker compose -f compose.test.yaml down
```

Тесты применяют настоящие миграции к PostgreSQL, проверяют сохранение и порядок
истории, разделение пользователей, очистку, открытый и ограниченный доступ,
ошибки API, тайм-ауты, длинные ответы и восстановление контекста после перезапуска
обработчика. Telegram и AI API подменяются, реальные сообщения не отправляются.
Тестовая база не использует данные рабочей базы и удаляется при остановке.

Для проверки стиля и адаптера:

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install --require-hashes -r requirements-dev.txt
ruff check .
ruff format --check .
node --test deploy/ai-worker.test.mjs
```

Для Node-тестов нужен Node.js 24. GitHub Actions запускает проверки при push и PR.

## Проверка в Telegram

1. Отправить `/start`, затем обычный вопрос. Получить ответ модели.
2. Сообщить контрольное слово и спросить его следующим сообщением.
3. Открыть бота с другого аккаунта. Контрольного слова в его истории быть не должно.
4. Выполнить `docker compose restart bot` и снова спросить контрольное слово.
5. Отправить `/clear` и убедиться, что новый диалог идёт без прежнего контекста.

Проверить сохранённые записи без вывода текста переписки:

```bash
docker compose exec db psql -U assistant -d assistant -c \
  'SELECT user_id, count(*) AS questions, count(answer) AS answers FROM turns GROUP BY user_id;'
```

## Обслуживание

```bash
docker compose logs --tail=100 bot
docker compose restart bot
docker compose exec -T db pg_dump -U assistant -d assistant -Fc > assistant.dump
```

Замените имя базы и пользователя, если меняли их в `.env`. Резервную копию храните
отдельно. Перед обновлением кода и миграциями делайте копию базы.
Обновление: `git pull`, затем `docker compose up -d --build`.
`docker compose down` сохраняет данные, `docker compose down -v` удаляет их.

Контейнер приложения работает без root и с файловой системой только для чтения.
Логи ограничены по размеру, токены и текст переписки в логи приложения не пишутся.
База использует постоянный том. Контейнеры перезапускаются после сбоя и запуска
Docker. На сервере службу Docker нужно включить: `sudo systemctl enable --now docker`.
Круглосуточная работа требует включённого сервера и доступной сети.

Проект рассчитан на один экземпляр бота. Ответ сохраняется до отправки в Telegram:
при ошибке доставки он может остаться только в базе. Гарантии доставки ровно один
раз нет. При остановке обработчики получают до 45 секунд на завершение.

Вопросы и часть истории передаются провайдеру AI. `/clear` удаляет историю из
рабочей базы, но не из Telegram, резервных копий или систем провайдера.
